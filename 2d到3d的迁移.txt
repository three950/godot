当前目标是把现有 2D 卡牌系统迁移到 3D 场景里，但不要重写 2D 卡牌逻辑。推荐采用**3D 包装器 + SubViewport 渲染 2D 卡牌**的混合架构。

核心方案：

```text
Card3DWrapper (Node3D)
├─ SubViewport
│  └─ Card2DInstance  # 现有 card/item/character/enemy/scene 等 2D 卡牌实例
├─ StaticBody3D 或 Area3D
│  └─ CollisionShape3D
├─ Sprite3D 或 MeshInstance3D  # 显示 SubViewport 的纹理
└─ Card3DInteractionAdapter.gd # 负责3D交互转发
```

不用管动态数字HP/ATK/DEF默认所有都为静态！

迁移原则：
1. 3D 层只负责空间摆放、3D 碰撞、射线点击/拖动检测。
2. 2D 卡牌继续负责卡面 UI、数据绑定、数值显示、已有状态逻辑。
3. 2D 的 `Area2D` 碰撞/堆叠不要硬搬到 3D；用 `Area3D` 或射线检测后，通过 Adapter 调用现有 2D 方法/信号。
4. 第一阶段先只实现显示：把现有 2D 卡牌实例放进 `SubViewport`，贴到 `Sprite3D`。
5. 第二阶段再做交互：`Card3DInteractionAdapter` 接收 3D 输入，然后转发给 2D 卡牌逻辑。
6. 性能上，默认 `SubViewport` 可以不持续刷新；无动态数字的卡牌可以静态刷新一次。有动态数字的卡牌在数值变化时刷新即可。

一句话：**3D 是外壳，2D 卡牌还是内核。先把卡牌作为 SubViewport 贴到 3D 里，动态数字继续用原来的 2D Label。**

#动态数字采用方案 A：继续让 2D 卡牌内部的 Label 更新，例如人物/敌人的 HP/ATK/DEF 仍由现有 AttributeLabels、BattleStates.stats_changed、update_stats() 流程维护。SubViewport 会把更新后的 2D UI 作为纹理显示到 3D 卡牌表面。暂时默认大多数卡牌没有动态数字，只有人物、敌人、资源/装备等已有动态显示需求的卡牌继续走 2D Label 更新。
